# Analyzer Name
Shared Return Calls

## Purpose
Exercise detection of a tail jump to an existing function and application of `CALL_RETURN` flow override.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/function/SharedReturnAnalyzer.java`, `SharedReturnJumpAnalyzer.java`, and `SharedReturnAnalysisCmd.java`.

## Test Scenario
The script seeds the destination function, analyzes a tail-call-shaped wrapper, and compares actual jump flow and flow overrides before and after analysis.

## Why This C++ Code Was Chosen
An optimized no-inline forwarding function gives MSVC a legitimate opportunity to emit an unconditional tail jump without assembly.

## Required Compiler Options
MSVC x64 optimization and linker retention options from `build.bat`.

## Required Auxiliary Files
The PE loader, disassembler, and `TEST/run_ghidra_python.bat` are required; no external database is used.

## Ghidra Analysis Options
Enable only `Shared Return Calls` after seeding the required destination function.

## Expected Results
When the compiler emits the expected jump, the analyzer may apply `CALL_RETURN`; the report records the actual result if it emits a call instead.

## Generated Markdown
`test_shared_return_calls.md` is generated by `run_ghidra.py` from flow state.

## Before target analysis
The report snapshots relevant functions and jump-flow overrides after fixture seeding and before `project.analyze(program)`.

## After target analysis
The report snapshots functions and flow overrides after the Shared Return Calls target.

## Delta
The report lists exact function and flow changes, distinguishing seeded destination functions from `CALL_RETURN` changes made by the target.

## Notes / Limitations
Tail-call lowering is compiler dependent, and the seeded destination is a prerequisite rather than a discovery. The existing sections below retain reproduction details.

This MSVC x64 PE fixture exercises `Shared Return Calls`: a jump to an existing
function whose return is shared by the jumping function. The report captures actual
flow overrides before and after analysis, so it remains valid if the compiler moves
the functions.

## Java contract

The implementation spans
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/function/SharedReturnAnalyzer.java`,
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/function/SharedReturnJumpAnalyzer.java`,
and
`Ghidra/Features/Base/src/main/java/ghidra/app/cmd/analysis/SharedReturnAnalysisCmd.java`.
It considers jump references to existing function entries, ignores conditional jumps
by default, and applies `CALL_RETURN` flow overrides only when the jump is not already
inside the destination function. The script seeds the target function because this
analyzer's contract requires an existing destination function; it does not claim that
the analyzer discovered that seed.

## Reproduction

Run `build.bat`, then
`TEST\\run_ghidra_python.bat \features\\analyzer\\test_data\\shared_return_calls\\run_ghidra.py`
from the repository root.

# Analyzer Name
Call Convention ID

## Purpose
Exercise identification of a calling convention for an eligible function with defined parameters.

## Original Ghidra Implementation
`Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerCallConventionAnalyzer.java`.

## Test Scenario
The harness resets `convention_target` to an unknown convention, adds integer parameters, runs the analyzer, and extracts convention and signature state.

## Why This C++ Code Was Chosen
Real arithmetic, multiple parameters, and a direct caller give the decompiler observable p-code without PDB or CRT dependencies.

## Required Compiler Options
MSVC x64 and the Windows linker as invoked by `build.bat`.

## Required Auxiliary Files
The PE loader, decompiler language support, and `TEST/run_ghidra_python.bat` are required; no PDB is required.

## Ghidra Analysis Options
Enable `Call Convention ID` after the script prepares the eligible function and disable unrelated boolean analyzers.

## Expected Results
The analyzer may recover the x64 convention or leave the function unknown; the generated report records the actual before/after state.

## Generated Markdown
`test_call_convention_id.md` is generated from final function metadata by `run_ghidra.py`.

## Notes / Limitations
Compiler-spec and decompiler versions control convention recovery. The existing sections below retain reproduction details.

## Behavior

The analyzer intentionally does not infer a convention for every function. The harness makes `convention_target` eligible by setting the unknown convention and adding defined `int` parameters, then records the recovered calling convention and signature. This is the same gating contract implemented by `findLocations()`.

## Dependencies

- MSVC x64 tools and the Windows linker are required by [`build.bat`](build.bat).
- PyGhidra must be launched through [`../../../../TEST/run_ghidra_python.bat`](../../../../TEST/run_ghidra_python.bat).
- The imported language must support p-code and expose more than one calling convention; the x86-64 Windows language does so.

## Limitations

The decompiler can recover the default x64 convention or leave the function unknown depending on compiler-spec and decompiler version. The setup edits the saved program's function metadata because a PE alone does not carry the user-defined parameter types required by the analyzer's eligibility test.

## Reproduction

Run `build.bat` in this directory. From the repository root, run `TEST\run_ghidra_python.bat \features\\analyzers\call_convention_id\\tests\\data\\\\run_ghidra.py`.

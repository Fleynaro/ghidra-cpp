# Analyzer Name
PDB MSDIA

## Purpose
Exercise the legacy Windows DIA-backed PDB analyzer and observe PDB-derived symbols, types, and program properties.

## Original Ghidra Implementation
`Ghidra/Features/PDB/src/main/java/ghidra/app/plugin/core/analysis/PdbAnalyzer.java`, with `PdbAnalyzerCommon.java` and `PdbParser.java`.

## Test Scenario
The `/Zi` PE and matching PDB contain user types, globals, and functions; `run_ghidra.py` selects the PDB and reports actual post-analysis artifacts.

## Why This C++ Code Was Chosen
Ordinary structs, enums, globals, and externally visible functions produce rich CodeView records without hand-authored XML or symbol rows.

## Required Compiler Options
MSVC x64 `/Zi /DEBUG:FULL` and matching PDB generation as invoked by `build.bat`.

## Required Auxiliary Files
The matching `.pdb`, Microsoft DIA support, PE loader, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
Enable only `PDB MSDIA` and select the matching PDB path through the analyzer option.

## Expected Results
When DIA is available, PDB properties, symbols, functions, and data types should appear in the generated report.

## Generated Markdown
`test_pdb_msdia.md` is generated by `run_ghidra.py` after analysis; the PE and PDB are build outputs.

## Before target analysis
The report snapshots PE-loader/CodeView properties, symbols, functions, and data types immediately before `project.analyze(program)`.

## After target analysis
The report snapshots the same PDB-related artifacts after the MSDIA target, preserving the observed state even when DIA cannot apply the raw PDB.

## Delta
The report lists exact property, symbol, function, and type changes, labels loader/default artifacts separately, and explicitly records a no-change MSDIA limitation when applicable.

## Notes / Limitations
Raw PDB processing is Windows/DIA dependent; a valid PDB can exist while the Java analyzer cannot consume it. The existing sections below retain reproduction details.

This directory contains a small MSVC x64 PE and matching `/Zi` PDB source fixture for
Ghidra's legacy `PDB MSDIA` analyzer. The source is intentionally rich in ordinary
user-defined types, globals, and externally visible C functions so that a successful
PDB load can be observed from symbols, function names, data types, and PDB program
properties rather than from guessed addresses.

## Navigation

- [`test_pdb_msdia.cpp`](test_pdb_msdia.cpp) defines the symbols and types expected to be discoverable from the PDB.
- [`build.bat`](build.bat) finds MSVC x64 tools and builds the PE with `/Zi`, `/DEBUG:FULL`, and a matching PDB.
- [`run_ghidra.py`](run_ghidra.py) creates a temporary project, reopens the imported executable with `project.openProgram(...)`, validates the selected PDB's existence and PE CodeView identity, explicitly selects `PDB MSDIA`, and writes a report from actual program state.
- [`test_pdb_msdia.exe`](test_pdb_msdia.exe) and [`test_pdb_msdia.pdb`](test_pdb_msdia.pdb) are trackable generated artifacts when the build prerequisites exist.
- [`test_pdb_msdia.md`](test_pdb_msdia.md) is generated only after the PyGhidra run completes.
- [`../../README.md`](../../README.md) describes the fixture collection boundary.

## Limitations

`PDB MSDIA` is the legacy analyzer at
`Ghidra/Features/PDB/src/main/java/ghidra/app/plugin/core/analysis/PdbAnalyzer.java`.
Raw PDB processing requires the Microsoft DIA SDK and is Windows-only. The build
script can create a valid matching PDB without installing DIA, but `run_ghidra.py`
will report an honest failure if the Ghidra installation cannot load DIA. A
preprocessed `.pdb.xml` is an alternative supported by the Java implementation, but
this fixture does not fabricate one. The runner uses the shared
[`../pdb_validation.py`](../pdb_validation.py) before invoking analysis, so a stale or
mispaired PDB fails instead of producing misleading DIA output.

## Reproduction

Run `build.bat` from this directory, then run
`TEST\\run_ghidra_python.bat \features\\analyzer\\test_data\\pdb_msdia\\run_ghidra.py`
from the repository root. Optional arguments are an executable, PDB, and report path.

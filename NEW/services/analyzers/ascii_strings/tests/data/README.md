# Analyzer Name
ASCII Strings

## Purpose
Exercise discovery and creation of valid ASCII string data in initialized accessible memory.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/string/StringsAnalyzer.java`.

## Test Scenario
The PE contains exported readable, short, unterminated, and non-ASCII candidates; `run_ghidra.py` enables only `ASCII Strings`, snapshots fixture-owned symbol ranges, and extracts positive strings plus negative context.

## Why This C++ Code Was Chosen
Initialized read-only arrays provide genuine bytes for the analyzer's memory and terminator checks. Exported symbols provide ownership boundaries so PE metadata strings are not reported as fixture results.

## Required Compiler Options
MSVC x64 and the Windows linker as invoked by `build.bat`.

## Required Auxiliary Files
The installed `Ghidra/Features/Base/data/stringngrams/StringModel.sng` and `TEST/run_ghidra_python.bat` are required; the model is not copied into the fixture.

## Ghidra Analysis Options
Enable only `ASCII Strings` with its default minimum-length, terminator, and string-model settings.

## Expected Results
The report contains the configured options, both fixture-owned positive strings, and all three negative controls. Negative controls remain visible but are not treated as positive discoveries; unrelated PE/linker strings are absent.

## Generated Markdown
`test_ascii_strings.md` is generated by `run_ghidra.py` from final defined string data.

## Notes / Limitations
N-gram scoring, addresses, and compiler-generated placement vary by Ghidra and MSVC version. The existing sections below retain reproduction details.

## Navigation

- [`test_ascii_strings.cpp`](test_ascii_strings.cpp) places positive and negative ASCII candidates in initialized read-only memory.
- [`build.bat`](build.bat) builds the CRT-free x64 PE with MSVC.
- [`run_ghidra.py`](run_ghidra.py) reopens the PE in a temporary project, runs only `ASCII Strings`, and extracts defined data only at exported fixture symbols.
- [`test_ascii_strings.exe`](test_ascii_strings.exe) is the generated input when MSVC is available.
- [`test_ascii_strings.md`](test_ascii_strings.md) is generated by PyGhidra when Ghidra and its string model are available.
- [`../README.md`](../../README.md) describes the analyzer fixture collection.

## Behavior

This fixture exercises `StringsAnalyzer`'s default minimum length, null-termination, accessible-memory filtering, and creation of string data. The report records the analyzer's configured options, symbol-owned positive ranges, and rejected negative controls without scanning every pointer or metadata string in the PE.

## Dependencies

- MSVC x64 tools and the Windows linker are required by [`build.bat`](build.bat).
- PyGhidra must be launched through [`../../../../TEST/run_ghidra_python.bat`](../../../../TEST/run_ghidra_python.bat).
- Ghidra's installed `Ghidra/Features/Base/data/stringngrams/StringModel.sng` is required by the authoritative analyzer; it is not copied into this fixture.

## Limitations

The n-gram model can change which text scores above threshold between Ghidra versions. The fixture therefore reports observed strings instead of asserting hard-coded addresses or scores. Exported fixture symbols define ownership, while their image addresses remain compiler/linker outputs.

## Reproduction

Run `build.bat` in this directory. From the repository root, run `TEST\run_ghidra_python.bat \features\\analyzers\ascii_strings\\tests\\data\\\\run_ghidra.py`.

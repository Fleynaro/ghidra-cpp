# Analyzer Name
Aggressive Instruction Finder

## Purpose
Exercise heuristic discovery of valid instructions in undefined executable bytes after the required repeated-function evidence has been prepared.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/prototype/analysis/AggressiveInstructionFinderAnalyzer.java`.

## Test Scenario
The C++ fixture supplies twenty-four repeated seed starts and one candidate body; `run_ghidra.py` clears only the candidate before analysis and extracts functions, bookmarks, and instruction state.

## Why This C++ Code Was Chosen
CRT-free no-inline functions provide real x64 bytes and stable PE retention without fabricating a function or bookmark in the harness.

## Required Compiler Options
MSVC x64 and the linker invoked by `build.bat`; `/OPT:NOICF` and the fixture's no-inline functions preserve repeated starts.

## Required Auxiliary Files
The local `build.bat`, the generated executable, and the repository `TEST/run_ghidra_python.bat` wrapper are required; no fixture-local database is required.

## Ghidra Analysis Options
Enable `Aggressive Instruction Finder` and leave `Create Analysis Bookmarks` enabled; the script disables unrelated boolean analyzers.

## Expected Results
Ghidra may rediscover the candidate and create an analysis bookmark when its heuristic checks pass; the report records the observed result.

## Generated Markdown
`test_aggressive_instruction_finder.md` is generated by `run_ghidra.py` from the analyzed program.

## Notes / Limitations
Compiler/linker layout and installed Ghidra heuristics can change whether the candidate is accepted. The existing sections below retain reproduction and limitation details.

## Behavior

This fixture exercises the analyzer's minimum-function guard, repeated-start hash, pseudo-disassembly validation, executable-byte scan, and optional analysis bookmark. The harness intentionally creates the undefined candidate state because a normal PE loader would otherwise already know the candidate as a function.

## Dependencies

- MSVC x64 tools and the Windows linker are required by [`build.bat`](build.bat).
- PyGhidra must be launched through [`../../../../TEST/run_ghidra_python.bat`](../../../../TEST/run_ghidra_python.bat).
- The target language must provide executable x64 disassembly and a pseudo-disassembler.

## Limitations

The Java analyzer is explicitly heuristic and warns that it may create bad code. Compiler optimization, linker layout, and instruction encodings can change whether the candidate satisfies the repeated-start and pseudo-disassembly tests. The report records actual functions and bookmarks instead of asserting discovery unconditionally.

## Reproduction

Run `build.bat` in this directory. From the repository root, run `TEST\run_ghidra_python.bat \features\\analyzers\aggressive_instruction_finder\\tests\\data\\\\run_ghidra.py`.

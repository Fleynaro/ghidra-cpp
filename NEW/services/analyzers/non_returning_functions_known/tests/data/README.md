# Analyzer Name
Non-Returning Functions - Known

## Purpose
Exercise exact-name lookup and no-return metadata application for a known PE function.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/analysis/NoReturnFunctionAnalyzer.java`, using `NonReturningFunctionNames.java` and the PE data constraints.

## Test Scenario
The exported local symbols `abort` and `_abort` exercise exact-name and leading-underscore normalization; the script extracts both flags/bookmarks plus the negative control.

## Why This C++ Code Was Chosen
An exported local name matches the authoritative PE list without linking the CRT implementation or fabricating an import.

## Required Compiler Options
MSVC x64 and the CRT-free linker configuration in `build.bat`.

## Required Auxiliary Files
`Ghidra/Features/Base/data/PEFunctionsThatDoNotReturn`, the PE loader, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
Enable only `Non-Returning Functions - Known` and its bookmark behavior.

## Expected Results
Both `abort` spellings should receive no-return metadata and bookmarks; `returning_control` should remain a negative name-matching control.

## Generated Markdown
`test_non_returning_functions_known.md` is generated by `run_ghidra.py`.

## Notes / Limitations
The separate external-placeholder/pointer branch requires a real import environment and is not covered by this standalone EXE. The existing sections below retain reproduction details.

This directory is an MSVC x64 PE fixture for Ghidra's `Non-Returning Functions
- Known` analyzer. The executable exports a local function named `abort`, which
is an exact entry in `Ghidra/Features/Base/data/PEFunctionsThatDoNotReturn`.

## Reproduction

Run `build.bat`, then the script through `TEST\\run_ghidra_python.bat`.

The real analyzer obtains names from the format-constrained PE data file; the
fixture's exported local symbol supplies that name without depending on a host
CRT or a machine-specific import library. A standalone EXE cannot exercise the
analyzer's separate external-placeholder/pointer branch without a real import
environment, so the report explicitly covers the local-symbol path and records
the actual external entries separately.

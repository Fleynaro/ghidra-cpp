# Analyzer Name
Function Start Search

## Purpose
Exercise architecture-pattern searches that create function starts and analysis bookmarks.

## Original Ghidra Implementation
`Ghidra/Features/BytePatterns/src/main/java/ghidra/app/analyzers/FunctionStartAnalyzer.java` and its phase analyzers `FunctionStartPostAnalyzer.java`, `FunctionStartDataPostAnalyzer.java`, and `FunctionStartFuncAnalyzer.java`.

## Test Scenario
Two stack-frame candidates are disassembled without pre-created functions; the script compares function entries and Function Start Search bookmarks before and after analysis.

## Why This C++ Code Was Chosen
Real x64 Windows stack prologues encourage the installed pattern files without inline assembly or guessed source-level addresses.

## Required Compiler Options
MSVC x64 `/Od /Oy-` and the retention options in `build.bat`.

## Required Auxiliary Files
The x86-64 Windows pattern XML/constraints, PE loader/disassembler, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
Enable the main and phase-specific `Function Start Search` options selected by `run_ghidra.py`.

## Expected Results
Only patterns accepted by the installed constraints should create entries/bookmarks; the report records enabled phases and observed discoveries.

## Generated Markdown
`test_function_start_search.md` is generated by `run_ghidra.py`.

## Notes / Limitations
Pattern availability and compiler prologues vary; the x64 Windows pre-search phase may have no matching constraints. The existing sections below retain reproduction details.

This directory is an MSVC x64 PE fixture for Ghidra's `Function Start Search`
family. Functions are compiled with stack frames so their starts contain the
real x86-64 Windows `SUB RSP, imm` patterns in
`Ghidra/Processors/x86/data/patterns/x86-64win_patterns.xml`.

## Navigation

- [`test_function_start_search.cpp`](test_function_start_search.cpp) exports two stack-using candidate functions and a caller.

- [`run_ghidra.py`](run_ghidra.py) reopens the imported program, enables the main and phase-specific Function Start Search analyzers, analyzes it, and extracts created entries/bookmarks.

## Reproduction

Run `build.bat`, then the script through `TEST\\run_ghidra_python.bat`.

The script disassembles bytes without code analysis and does not pre-create the
candidate functions. The observable result is therefore the actual pattern
searcher-created entries and its analysis bookmarks, not labels guessed from
the C++ source. In the verified standalone PyGhidra environment the x64
pattern searcher did not schedule a function from this exported-PE fixture,
so the generated report intentionally records zero created functions and zero
bookmarks. This is a real limitation of triggering the phase from a standalone
EXE, not fabricated output. The x64 Windows pre-pattern file also has no
matching compiler section in the authoritative constraints, so the report does
not pretend that the unavailable pre-search phase ran.

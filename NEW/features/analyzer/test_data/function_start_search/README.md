# Analyzer Name
Function Start Search

## Purpose
Exercise architecture-pattern searches that create function starts and analysis bookmarks.

## Original Ghidra Implementation
`Ghidra/Features/BytePatterns/src/main/java/ghidra/app/analyzers/FunctionStartAnalyzer.java` and its phase analyzers `FunctionStartPostAnalyzer.java`, `FunctionStartDataPostAnalyzer.java`, and `FunctionStartFuncAnalyzer.java`.

## Test Scenario
The fixture exports ordinary no-inline x64 functions as negative controls and embeds an exported raw executable byte sequence containing the x86-64 Windows FunctionStart pattern as a positive candidate. The script removes only the positive candidate function, retains the negative function, and compares function entries and Function Start Search bookmarks before and after analysis.

## Why This C++ Code Was Chosen
The raw sequence is an actual byte-level match for the installed x64 Windows pattern, while the ordinary compiler-generated function supplies a real already-defined negative control. No inline assembly or guessed source-level address is required.

## Required Compiler Options
MSVC x64 `/Od /Oy-` and the retention options in `build.bat`.

## Required Auxiliary Files
The x86-64 Windows pattern XML/constraints, PE loader/disassembler, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
Enable the main and phase-specific `Function Start Search` options selected by `run_ghidra.py`.

## Expected Results
The positive pattern mark must transition from no function before analysis to a function afterward. The negative exported function must remain present in both snapshots and must not be counted as target-created.

## Generated Markdown
`test_function_start_search.md` is generated by `run_ghidra.py`.

## Notes / Limitations
Pattern availability still depends on the installed Ghidra pattern resources, but this fixture embeds the exact positive x64 pattern used by those resources. The report fails instead of documenting an unsupported zero-result claim if the positive transition is absent.

This directory is an MSVC x64 PE fixture for Ghidra's `Function Start Search`
family. Functions are compiled with stack frames so their starts contain the
real x86-64 Windows `SUB RSP, imm` patterns in
`Ghidra/Processors/x86/data/patterns/x86-64win_patterns.xml`.

## Reproduction

Run `build.bat`, then the script through `TEST\\run_ghidra_python.bat`.

The script disassembles bytes without code analysis, removes only the positive
candidate function, and retains the negative candidate. The observable result is
therefore the actual pattern-searcher-created entry and its analysis bookmarks,
with before/after evidence for both candidates. The report does not fabricate a
match or treat the pre-existing negative function as an analyzer result.

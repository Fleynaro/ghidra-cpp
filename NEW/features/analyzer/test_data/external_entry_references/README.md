# Analyzer Name
External Entry References

## Purpose
Exercise creation of functions from valid external-entry references supplied by a PE export table.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/function/ExternalEntryFunctionAnalyzer.java`.

## Test Scenario
Three exported code locations are disassembled and analyzed; the script compares export/external-entry addresses with function entries before and after analysis.

## Why This C++ Code Was Chosen
The PE export table is a real standalone-EXE source of external entries, unlike fabricated external database state.

## Required Compiler Options
MSVC x64 and linker export retention as invoked by `build.bat`.

## Required Auxiliary Files
The PE loader, disassembler, and `TEST/run_ghidra_python.bat` are required; no external symbol database is used.

## Ghidra Analysis Options
Enable only `External Entry References` after explicit disassembly.

## Expected Results
Exported locations with valid instructions and no fall-through conflict may become function entries; the report records rejected entries too.

## Generated Markdown
`test_external_entry_references.md` is generated by `run_ghidra.py` from actual program state.

## Notes / Limitations
A standalone EXE cannot exercise callers outside the image or hand-edited external tables. The existing sections below retain reproduction details.

This directory is an MSVC x64 PE fixture for Ghidra's `External Entry
References` analyzer. The PE exports three real code entry points. Export
symbols become external-entry references during PE import; after explicit
disassembly, the analyzer should create functions where instructions exist and
the entry is not a fall-through location.

## Reproduction

Run `build.bat`, then
`TEST\\run_ghidra_python.bat NEW\\features\\analyzer\\test_data\\external_entry_references\\run_ghidra.py`.

An ordinary standalone EXE cannot manufacture a caller outside the image or a
hand-edited external-entry table; this fixture therefore uses the real PE
export table, which is the portable artifact that supplies external entry
references. The report records the actual entries and any entries rejected by
the analyzer's instruction/fall-through checks rather than claiming coverage
of unavailable external database state.

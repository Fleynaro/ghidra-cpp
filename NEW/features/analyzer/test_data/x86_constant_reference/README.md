# Analyzer Name
x86 Constant Reference

## Purpose
Exercise the x86-specific LEA constant propagation path that creates an operand DATA reference.

## Original Ghidra Implementation
`Ghidra/Processors/x86/src/main/java/ghidra/app/plugin/core/analysis/X86Analyzer.java`, using `ConstantPropagationAnalyzer.java`.

## Test Scenario
An inline-assembly x86 `LEA` computes the address of initialized data; the script compares operand references before and after the processor-specific analyzer.

## Why This C++ Code Was Chosen
MSVC x86 inline assembly forces the exact LEA pattern and prevents x64 code generation from selecting another analyzer path.

## Required Compiler Options
MSVC x86 selected by `VsDevCmd.bat -arch=x86`, with inline assembly enabled as invoked by `build.bat`.

## Required Auxiliary Files
The x86 PE language, PE loader, and `TEST/run_ghidra_python.bat` are required; no auxiliary database is used.

## Ghidra Analysis Options
Enable only the exact processor-specific analyzer selected by `run_ghidra.py`.

## Expected Results
The imported LEA should gain a DATA reference to `target_value` when propagation succeeds; the report records actual rows.

## Generated Markdown
`test_x86_constant_reference.md` is generated by `run_ghidra.py`.

## Notes / Limitations
The analyzer claims only processor `x86`; instruction encoding and address layout remain toolchain dependent. The existing sections below retain reproduction details.

This directory contains a dedicated 32-bit MSVC PE with an x86 `LEA` that computes
the address of initialized data. The generated report compares operand references
before and after the `x86 Constant Reference Analyzer` runs and records the created
DATA reference to the fixture value.

## Why x86 is mandatory

The base implementation is
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/analysis/ConstantPropagationAnalyzer.java`.
The x86 specialization is
`Ghidra/Processors/x86/src/main/java/ghidra/app/plugin/core/analysis/X86Analyzer.java`.
`X86Analyzer.canAnalyze()` (lines 40-44) claims only the processor named `x86`, and
its `flowConstants()` override (lines 47-99) specifically evaluates `LEA`, converts
the propagated value to an address, and adds an operand DATA reference when the
address is in memory (lines 55-69). The x86 PE and x86 build mode are therefore
required to test the requested behavior; an x64 fixture would select a different
language and analyzer.

Run `build.bat`, then execute
`TEST\\run_ghidra_python.bat NEW\\features\\analyzer\\test_data\\x86_constant_reference\\run_ghidra.py`
from the repository root.

# Analyzer Name
Function ID

## Purpose
Exercise real FID database population, function hashing, matching, and target markup.

## Original Ghidra Implementation
`Ghidra/Features/FunctionID/src/main/java/ghidra/feature/fid/analyzer/FidAnalyzer.java`, with `ApplyFidEntriesCommand.java` and `FidService.java` support.

## Test Scenario
A library PE and target PE contain identical function bytes; `run_ghidra.py` builds the packed `.fidb` through Ghidra APIs and extracts target labels, comments, and bookmarks.

## Why This C++ Code Was Chosen
The deterministic arithmetic body exceeds FID's minimum and is compiled twice, giving the production service genuine matching bytes rather than fabricated hashes.

## Required Compiler Options
MSVC x64 and the linker as invoked by `build.bat`; both builds must preserve identical function bytes.

## Required Auxiliary Files
The generated library PE, packed `.fidb`, PE loader, Function ID feature, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
Enable only `Function ID` after the script creates and selects a language-compatible FID database.

## Expected Results
The target may receive FID-derived labels/comments/bookmarks when the real hash and score rules match; database population is reported separately.

## Generated Markdown
`test_function_id.md` is generated by `run_ghidra.py`; the `.fidb` is also generated and is not hand-authored.

## Notes / Limitations
FID thresholds, language IDs, and database formats are version dependent. The existing sections below retain reproduction details.

This directory is an MSVC x64 PE fixture for Ghidra's `Function ID` analyzer.
It includes a second executable with identical compiled function bytes. The
PyGhidra harness imports that executable as a project program, uses the actual
`FidFileManager`/`FidDB`/`FidService` ingestion APIs to create the auxiliary
[`test_function_id.fidb`](test_function_id.fidb), then runs the analyzer against
the target PE. No hashes, database rows, or labels are invented by the script.

## Reproduction

Run `build.bat`, then run the fixture script through
`TEST\\run_ghidra_python.bat`. The script accepts an optional target executable
and report path; the library PE and `.fidb` remain beside the script.

The real mechanism matters here: `FidService.hashFunction` produces records via
`FidServiceLibraryIngest`, and `ApplyFidEntriesCommand` queries those records
through `FidQueryService`. The report distinguishes database population from
the target's observable FID markup and records the active analysis options.

The repository's current source uses `FidFilter`; the installed Ghidra 12.1.3
runtime used for the generated artifact predates that class and exposes the
equivalent `LanguageID` overload. The script selects the available production
API, and the generated report confirms the actual `FidService` query matches.

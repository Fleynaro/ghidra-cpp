# Analyzer Name
Decompiler Switch Analysis

## Purpose
Exercise recovery of computed switch dispatch, case references, labels, and repaired function bodies.

## Original Ghidra Implementation
`Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerSwitchAnalyzer.java` and `DecompilerSwitchAnalysisCmd.java`.

## Test Scenario
A dense eight-case switch is the positive case and a sparse switch is a negative boundary; the script extracts labels and computed references.

## Why This C++ Code Was Chosen
Optimized dense integral cases encourage a real jump table while the sparse case documents that ordinary conditional chains are not switches.

## Required Compiler Options
MSVC x64 `/O2 /Ob0 /GL-` with linker retention options from `build.bat`.

## Required Auxiliary Files
Ghidra Decompiler support, the PE loader/disassembler, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
Enable only `Decompiler Switch Analysis`; functions and instructions are prepared explicitly.

## Expected Results
The dense function may receive a `switchD` label and case references; the report does not assert pseudocode or unstable addresses.

## Generated Markdown
`test_decompiler_switch_analysis.md` is generated by `run_ghidra.py`.

## Notes / Limitations
Compiler lowering may choose a conditional chain, producing no honest switch discovery. The existing sections below retain reproduction details.

## Fixture Design

The dense eight-case switch is the positive case for computed dispatch; a sparse three-case switch is a negative boundary. A volatile selector, noinline functions, `/O2`, and `/Ob0` preserve the compiler's dynamic dispatch without assembly or undefined behavior.

## Ghidra Java Contract

The exact analyzer is [`Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerSwitchAnalyzer.java`](../../../../../Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerSwitchAnalyzer.java). It finds computed jumps, decompiles candidate functions, and invokes [`DecompilerSwitchAnalysisCmd.java`](../../../../../Ghidra/Features/Decompiler/src/main/java/ghidra/app/cmd/function/DecompilerSwitchAnalysisCmd.java), which labels `switchD`, adds case references, disassembles cases, and repairs function bodies. The report extracts labels and computed references, not unstable pseudocode.

## Dependencies

MSVC x64 is required for the PE fixture. PyGhidra requires the repository wrapper, PE loader, disassembler, and Decompiler feature. Functions and instructions are prepared explicitly; no unrelated analysis boolean is enabled.

## Limitations

MSVC may choose a conditional chain for a dense switch under a different compiler version, in which case no switch discovery is honestly reported. The fixture does not fake a `switchD` label or inject case references. Absolute addresses and pseudocode are intentionally excluded.

## Reproduction

Run `build.bat`, then from the repository root run `TEST\run_ghidra_python.bat NEW\features\analyzer\test_data\decompiler_switch_analysis\run_ghidra.py`. Optional executable/report arguments are supported.

## Generated Artifacts

The expected generated files are `test_decompiler_switch_analysis.exe` and `test_decompiler_switch_analysis.md`. They are produced only by the stated build and analysis workflows.

## Validation

Validation completed with MSVC 2022 x64 compilation/linking, isolated project reopen through `project.openProgram(...)`, target-only decompiler analysis, and report inspection. The generated report contains one `switchD` label and eight computed case references.

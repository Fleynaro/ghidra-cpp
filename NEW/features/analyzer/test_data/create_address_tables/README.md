# Analyzer Name
Create Address Tables

## Purpose
Exercise recognition of a contiguous valid pointer run, pointer-data creation, and the Address Table bookmark.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/disassembler/AddressTableAnalyzer.java` with entry validation in `AddressTable.java`.

## Test Scenario
The `.rdata` fixture table contains relocatable function pointers followed by a non-pointer sentinel; the script extracts pointer data and bookmarks.

## Why This C++ Code Was Chosen
Exported no-inline targets and a const pointer array produce real relocations and undefined imported data without predefining the table in Ghidra.

## Required Compiler Options
MSVC x64 and the linker as invoked by `build.bat`; `/OPT:NOICF` and `/OPT:NOREF` preserve targets and table contents.

## Required Auxiliary Files
The PE loader, disassembler, and `TEST/run_ghidra_python.bat` are required; no CRT or third-party dependency is needed.

## Ghidra Analysis Options
Enable `Create Address Tables` and its bookmark option while disabling unrelated boolean analyzers.

## Expected Results
The generated Ghidra 12.1.3 report records pointer data for the contiguous entries and no bookmark; the script preserves that observed analyzer state rather than fabricating the expected bookmark. The sentinel is not reported as a table entry.

## Generated Markdown
`test_create_address_tables.md` is generated by `run_ghidra.py`; the executable is generated by `build.bat`.

## Notes / Limitations
Minimum-size, relocation, alignment, and memory heuristics remain controlled by the installed analyzer. The existing sections below retain validation details.

## Fixture Design

The source uses exported no-inline functions as pointer targets and places a const pointer array in `.rdata`. The following non-pointer value makes the expected table boundary observable. The construction mirrors the undefined pointer-run cases in [`Ghidra/Features/Base/src/test/java/ghidra/app/plugin/core/disassembler/AddressTableAnalyzerTest.java`](../../../../../Ghidra/Features/Base/src/test/java/ghidra/app/plugin/core/disassembler/AddressTableAnalyzerTest.java).

## Ghidra Java Contract

The exact implementation is [`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/disassembler/AddressTableAnalyzer.java`](../../../../../Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/disassembler/AddressTableAnalyzer.java). It requires a 32- or 64-bit address space, scans loaded searchable memory, calls `AddressTable.getEntry(...)`, creates pointer data, and optionally creates an `Analysis` bookmark with category `Address Table`. The script reports only those bookmark and pointer-data results.

## Dependencies

The executable depends on MSVC x64 `cl.exe`/`link.exe` and the repository PyGhidra wrapper [`TEST/run_ghidra_python.bat`](../../../../../TEST/run_ghidra_python.bat). The analysis script depends on the PE loader, disassembler command, and target analyzer shipped by the Ghidra installation. No CRT or third-party C++ dependency is required.

## Limitations

The fixture does not claim that every valid pointer run is a table; minimum-size, alignment, relocation, and memory-content heuristics remain controlled by the original analyzer. Generated addresses are extracted from the PE rather than hard-coded. No executable or markdown artifact is checked in when the local MSVC/PyGhidra toolchains are unavailable.

## Reproduction

Run `build.bat` from this directory. From the repository root run `TEST\run_ghidra_python.bat NEW\features\analyzer\test_data\create_address_tables\run_ghidra.py`. Optional arguments are an input executable and output markdown path.

## Generated Artifacts

The build creates `test_create_address_tables.exe`; the PyGhidra script creates `test_create_address_tables.md`. They are generated outputs, not hand-authored evidence.

## Validation

Validation completed with MSVC 2022 x64 compilation/linking, the repository PyGhidra wrapper, project save/reopen through `project.openProgram(...)`, target-only analysis, and generated-report inspection. The report records the analyzer's actual pointer/bookmark state.

# Analyzer Name
Stack

## Purpose
Exercise stack reference, frame, and local-variable discovery for existing functions.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/function/StackVariableAnalyzer.java` and `NewFunctionStackAnalysisCmd.java`.

## Test Scenario
Volatile locals, an address-taken local, and a nested call are disassembled and analyzed; the script extracts stack references, variables, and frame information.

## Why This C++ Code Was Chosen
Frame-pointer-friendly MSVC code creates real stack storage and call boundaries without relying on debug metadata or a CRT.

## Required Compiler Options
MSVC x64 `/Oy-` and the deterministic options in `build.bat`.

## Required Auxiliary Files
The PE loader, disassembler, and `TEST/run_ghidra_python.bat` are required; no PDB is required.

## Ghidra Analysis Options
Enable `Stack` and `Stack.Create Local Variables`, disable parameter creation as configured by the script, and disable unrelated analyzers.

## Expected Results
The report records stack artifacts that the installed analyzer can prove; it does not substitute source-level local names.

## Generated Markdown
`test_stack.md` is generated by `run_ghidra.py` from the resulting listing.

## Notes / Limitations
Recovered locals, frame formatting, and references vary with compiler and Ghidra analysis. The existing sections below retain reproduction details.

This MSVC x64 PE fixture exercises Ghidra's `Stack` analyzer with stack-resident
locals, address-taken locals, and a call boundary. The report extracts the functions'
actual stack references, variables, and frame information after analysis.

## Java contract

The exact analyzer is
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/function/StackVariableAnalyzer.java`,
which finds defined function entries and dispatches
`Ghidra/Features/Base/src/main/java/ghidra/app/cmd/function/NewFunctionStackAnalysisCmd.java`
for stack-variable/reference creation. `Stack` is a function analyzer scheduled after
data-type propagation. The harness enables the explicit `Subroutine References`
prerequisite so the called worker is defined before `Stack`, enables
`Stack.Create Local Variables`, disables parameter creation, and reports the resulting
stack references and local symbols without claiming source-level variables were
recovered if MSVC/Ghidra cannot prove them.

## Reproduction

Run `build.bat`, then
`TEST\\run_ghidra_python.bat NEW\\features\\analyzer\\test_data\\stack\\run_ghidra.py`
from the repository root.

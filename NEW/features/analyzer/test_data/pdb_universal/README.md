# Analyzer Name
PDB Universal

## Purpose
Exercise platform-independent raw PDB2 parsing and application of PDB-derived metadata.

## Original Ghidra Implementation
`Ghidra/Features/PDB/src/main/java/ghidra/app/plugin/core/analysis/PdbUniversalAnalyzer.java`, with `PdbAnalyzerCommon.java`, `PdbParser.java`, and `DefaultPdbApplicator.java`.

## Test Scenario
The matching `/Zi` PE/PDB contains records, an enum, a global, and functions; the script selects `PDB Universal` and extracts applied artifacts and properties.

## Why This C++ Code Was Chosen
Named fields and ordinary C functions generate genuine PDB symbols and types while remaining independent of CRT behavior.

## Required Compiler Options
MSVC x64 `/Zi /DEBUG:FULL` and matching PDB generation as invoked by `build.bat`.

## Required Auxiliary Files
The matching `.pdb`, PDB feature, PE loader, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
Enable only `PDB Universal` and set its PDB path before analysis.

## Expected Results
PDB-derived symbols, functions, data types, and program properties should be reported when the reader and applicator accept the matching file.

## Generated Markdown
`test_pdb_universal.md` is generated by `run_ghidra.py`; the PE and PDB are build outputs.

## Notes / Limitations
PDB matching and applicator details are version dependent even though Universal is platform independent. The existing sections below retain reproduction details.

This directory contains the parallel MSVC x64 `/Zi` fixture for Ghidra's
platform-independent `PDB Universal` analyzer. It uses the same kind of PE/PDB
metadata as the MSDIA fixture while exercising the raw PDB2 reader and applicator.

## Implementation boundary

The Java implementation is
`Ghidra/Features/PDB/src/main/java/ghidra/app/plugin/core/analysis/PdbUniversalAnalyzer.java`,
with shared lookup in
`Ghidra/Features/PDB/src/main/java/ghidra/app/plugin/core/analysis/PdbAnalyzerCommon.java`
and raw parsing in
`Ghidra/Features/PDB/src/main/java/ghidra/app/util/bin/format/pdb2/pdbreader/PdbParser.java`.
Universal reads raw PDB files without XML and schedules function-internals and final
reporting work. The report labels PDB-derived symbols, functions, data types, and
program properties explicitly; it never treats source-level expectations as observed
results. Unlike MSDIA, Universal is Java/platform-independent, although it still
requires a valid PE/PDB match and may expose version-dependent applicator details.

## Reproduction

Run `build.bat`, then
`TEST\\run_ghidra_python.bat NEW\\features\\analyzer\\test_data\\pdb_universal\\run_ghidra.py`
from the repository root. Optional arguments are an executable, PDB, and report path.

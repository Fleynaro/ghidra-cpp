# Analyzer Name
Decompiler Parameter ID

## Purpose
Exercise decompiler-based recovery and commitment of function parameters and types.

## Original Ghidra Implementation
`Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerFunctionAnalyzer.java` and `DecompilerParameterIdCmd.java`.

## Test Scenario
The exported three-parameter function is first processed by PDB Universal using the matching MSVC PDB, then prepared and analyzed by Decompiler Parameter ID. The report snapshots parameters, types, storage, and return type before and after the target analyzer.

## Why This C++ Code Was Chosen
Real Microsoft x64 ABI integer and pointer use is paired with compiler-emitted CodeView/PDB type metadata. This gives Decompiler Parameter ID meaningful source types to preserve while still exercising its decompiler-based command and storage recovery.

## Required Compiler Options
MSVC x64 and the deterministic options in `build.bat`, including no-inline behavior and `/DEBUG:FULL` PDB emission.

## Required Auxiliary Files
Ghidra Decompiler and PDB Universal support, the PE loader/disassembler, the matching `.pdb`, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
The script enables `PDB Universal` first to import types, then keeps it enabled with `Decompiler Parameter ID` while the target runs.

## Expected Results
The target should preserve a recovered parameter list and meaningful non-undefined storage/type facts when decompilation succeeds; setup artifacts are not counted as discoveries.

## Generated Markdown
`test_decompiler_parameter_id.md` is generated by `run_ghidra.py`.

## Notes / Limitations
Parameter names, inferred types, and storage formatting vary across decompiler versions. The existing sections below retain reproduction details.

## Fixture Design

`parameter_fixture` uses an integer, character-pointer, and output-pointer parameter, with observable reads/writes and no CRT dependency. Exported function symbols make setup deterministic. The script prepares code and Function objects because the Java analyzer operates on an existing function set; preparation is not reported as a discovery.

## Ghidra Java Contract

The implementation is [`Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerFunctionAnalyzer.java`](../../../../../Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerFunctionAnalyzer.java). Its `added(...)` method constructs [`DecompilerParameterIdCmd.java`](../../../../../Ghidra/Features/Decompiler/src/main/java/ghidra/app/cmd/function/DecompilerParameterIdCmd.java), which builds a dependency graph, decompiles functions, and commits parameters/types. The report extracts only the target function's parameters, types, storage, and return type.

## Dependencies

The fixture needs MSVC x64 and a Ghidra installation with Decompiler and PDB Universal support. The script uses the repository PyGhidra wrapper and the PE loader/disassembler; the generated PDB is a required matching input and no CRT imports are used.

## Limitations

Decompiler parameter names and storage formatting are Ghidra outputs and may change between versions or compiler lowering choices. The report intentionally avoids pseudocode and absolute image addresses, but fails if post-analysis types regress to undefined/unknown placeholders. A missing or failed decompilation is not converted into a fabricated result.

## Reproduction

Run `build.bat`, then `TEST\run_ghidra_python.bat NEW\features\analyzer\test_data\decompiler_parameter_id\run_ghidra.py` from the repository root. Optional executable, PDB, and report arguments are accepted.

## Generated Artifacts

`test_decompiler_parameter_id.exe` and `.pdb` are generated by MSVC; `test_decompiler_parameter_id.md` is generated by PyGhidra. None is a placeholder.

## Validation

Validation completed with MSVC 2022 x64 compilation/linking, PDB Universal type import, project save/reopen through `project.openProgram(...)`, explicit function preparation, target analysis, and report inspection. The generated report contains one fixture function with three meaningful recovered parameters before and after the target, plus an explicit Delta section.

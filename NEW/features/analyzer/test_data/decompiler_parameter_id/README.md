# Analyzer Name
Decompiler Parameter ID

## Purpose
Exercise decompiler-based recovery and commitment of function parameters and types.

## Original Ghidra Implementation
`Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerFunctionAnalyzer.java` and `DecompilerParameterIdCmd.java`.

## Test Scenario
The exported three-parameter function is disassembled and created before target-only analysis; the report extracts parameters, types, storage, and return type.

## Why This C++ Code Was Chosen
Real Microsoft x64 ABI integer and pointer use creates recoverable p-code without PDB data, CRT imports, or hand-authored function metadata.

## Required Compiler Options
MSVC x64 and the deterministic options in `build.bat`, including no-inline behavior.

## Required Auxiliary Files
Ghidra Decompiler support, the PE loader/disassembler, and `TEST/run_ghidra_python.bat` are required.

## Ghidra Analysis Options
Enable only `Decompiler Parameter ID`; the script prepares the prerequisite functions explicitly.

## Expected Results
The target should expose a recovered parameter list and storage/type facts when decompilation succeeds; setup artifacts are not counted as discoveries.

## Generated Markdown
`test_decompiler_parameter_id.md` is generated by `run_ghidra.py`.

## Notes / Limitations
Parameter names, inferred types, and storage formatting vary across decompiler versions. The existing sections below retain reproduction details.

## Navigation

- [`test_decompiler_parameter_id.cpp`](test_decompiler_parameter_id.cpp) defines a three-parameter Microsoft x64 function and a direct caller.

## Fixture Design

`parameter_fixture` uses an integer, character-pointer, and output-pointer parameter, with observable reads/writes and no CRT dependency. Exported function symbols make setup deterministic. The script prepares code and Function objects because the Java analyzer operates on an existing function set; preparation is not reported as a discovery.

## Ghidra Java Contract

The implementation is [`Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerFunctionAnalyzer.java`](../../../../../Ghidra/Features/Decompiler/src/main/java/ghidra/app/plugin/core/analysis/DecompilerFunctionAnalyzer.java). Its `added(...)` method constructs [`DecompilerParameterIdCmd.java`](../../../../../Ghidra/Features/Decompiler/src/main/java/ghidra/app/cmd/function/DecompilerParameterIdCmd.java), which builds a dependency graph, decompiles functions, and commits parameters/types. The report extracts only the target function's parameters, types, storage, and return type.

## Dependencies

The fixture needs MSVC x64 and a Ghidra installation with the Decompiler language support. The script uses the repository PyGhidra wrapper and the PE loader/disassembler. It does not require PDB data, CRT imports, or another analysis boolean.

## Limitations

Decompiler parameter names, inferred types, and storage formatting are Ghidra outputs and may change between Ghidra versions or compiler lowering choices. The report intentionally avoids pseudocode and absolute image addresses. A missing or failed decompilation is not converted into a fabricated result.

## Reproduction

Run `build.bat`, then `TEST\run_ghidra_python.bat NEW\features\analyzer\test_data\decompiler_parameter_id\run_ghidra.py` from the repository root. Optional executable/report arguments are accepted.

## Generated Artifacts

`test_decompiler_parameter_id.exe` is generated by MSVC; `test_decompiler_parameter_id.md` is generated by PyGhidra. Neither is a placeholder.

## Validation

Validation completed with MSVC 2022 x64 compilation/linking, project save/reopen through `project.openProgram(...)`, explicit function preparation, target-only analysis, and report inspection. The generated report contains one fixture function with three recovered parameters.

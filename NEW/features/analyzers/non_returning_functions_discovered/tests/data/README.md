# Analyzer Name
Non-Returning Functions - Discovered

## Purpose
Exercise thresholded discovery of a non-returning function from post-call `INT3` evidence.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/analysis/FindNoReturnFunctionsAnalyzer.java`.

## Test Scenario
Three exported callers invoke one target and execute `__debugbreak`, while a fourth caller has an ordinary fallthrough; the script seeds real functions, configures threshold three, and extracts flags, flow overrides, and bookmarks.

## Why This C++ Code Was Chosen
MSVC `__debugbreak` emits the authoritative x86 `INT3` instruction while preserving a CRT-free executable and independent evidence sites.

## Required Compiler Options
MSVC x64 with intrinsic support and linker retention as invoked by `build.bat`.

## Required Auxiliary Files
The PE loader/disassembler and `TEST/run_ghidra_python.bat` are required; no external no-return database is needed for this discovered path.

## Ghidra Analysis Options
Enable only `Non-Returning Functions - Discovered`, set threshold to three, and disable `Repair Flow Damage` as configured by the script.

## Expected Results
The target should be marked non-returning after three independent indications, and all four target call sites should receive flow repair; the harness must not set the flag or overrides itself.

## Generated Markdown
`test_non_returning_functions_discovered.md` is generated by `run_ghidra.py`.

## Notes / Limitations
The evidence is processor and instruction-pattern dependent, and function seeding is an explicit prerequisite. The existing sections below retain reproduction details.

This directory is an MSVC x64 PE fixture for Ghidra's `Non-Returning Functions
- Discovered` analyzer. Three exported callers invoke one exported target and
each has a real x86 `INT3` immediately after the call, generated by the MSVC
`__debugbreak` intrinsic. The authoritative analyzer counts these indications
and marks the target when the configured threshold of three is reached.

## Reproduction

Run `build.bat`, then the script through `TEST\\run_ghidra_python.bat`.

The harness creates functions only at real exported starts so the analyzer sees
the same existing-function prerequisite it would see after disassembly. It does
not set no-return flags or flow overrides itself. The expected observable is a
target marked non-returning after three independent `INT3 interrupt after call`
indications; `Repair Flow Damage` is disabled so body repair does not obscure
that result.

# Analyzer Name
Scalar Operand References

## Purpose
Exercise conversion of eligible scalar operands into analysis-source references.

## Original Ghidra Implementation
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/analysis/ScalarOperandAnalyzer.java`.

## Test Scenario
Fixed image-address immediates for data, code, and a second mapped section are disassembled and analyzed beside address-shaped out-of-image and small numeric values. The script snapshots scalar operands before and after analysis and reports both accepted and rejected outcomes.

## Why This C++ Code Was Chosen
The fixed PE base and section alignment make two address-like immediate operands stable. No-inline functions force those immediates to remain scalar operands, while out-of-image and below-threshold values remain negative controls.

## Required Compiler Options
MSVC x64 and the deterministic linker configuration in `build.bat`.

## Required Auxiliary Files
The PE loader, disassembler, and `TEST/run_ghidra_python.bat` are required; no external database is used.

## Ghidra Analysis Options
Enable only `Scalar Operand References` after explicit disassembly and disable unrelated boolean analyzers.

## Expected Results
The three fixed in-image addresses gain analysis references. The out-of-image address-like value and small values remain visible without references, demonstrating the Java filters instead of dropping negative context.

## Generated Markdown
`test_scalar_operand_references.md` is generated by `run_ghidra.py` from observed scalar/reference rows.

## Before target analysis
The report snapshots every relevant scalar operand and its operand references after disassembly and before `project.analyze(program)`.

## After target analysis
The report snapshots those operands after the Scalar Operand References target, including accepted and rejected controls.

## Delta
The report keys exact added, removed, and changed outcomes by instruction address and operand index.

## Notes / Limitations
MSVC encoding and linker layout determine which operands materialize and are reportable. The existing sections below retain reproduction details.

This MSVC x64 PE fixture exercises Ghidra's `Scalar Operand References` analyzer
with address-valued constants and ordinary numeric values. It intentionally leaves
the compiler free to choose instruction encodings; the report extracts scalar
operand references that Ghidra actually creates.

## Java contract

The exact implementation is
`Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/analysis/ScalarOperandAnalyzer.java`.
It scans scalar operand objects, gives relocation matches priority, rejects common
numeric sentinels and small values, tests address spaces and memory, avoids offcut
function references, and adds analysis-source operand references. The harness first
disassembles executable bytes without code analysis, disables every unrelated boolean
analyzer, enables only this analyzer, and records observed scalar/reference rows.
The fixture deliberately fixes the PE image base and uses section-aligned addresses for its positive controls. The report still obtains the actual scalar values and references from Ghidra rather than assuming that every immediate was accepted.

## Reproduction

Run `build.bat`, then
`TEST\\run_ghidra_python.bat NEW\\features\\analyzer\\test_data\\scalar_operand_references\\run_ghidra.py`
from the repository root.
